# Reconcile and learn

Check activation with `node PLUGIN_ROOT/runtime/cli.mjs status --root PROJECT`, using this skill's installed plugin root. If inactive, continue through the native host without Conceptor. Do not enable it implicitly.

Use this skill for consequential decisions raised in discussion, planning, or work, even when implementation is not requested. Read the affected Concepts and typed Relations. Record the accepted decision and its reasons in the owning record before dependent implementation or handoff. Include relevant priorities, prerequisites, sequencing, constraints, and exceptions.

Keep proposals, observations, and accepted decisions distinct. Mark a candidate record or observed Relation accepted only after an explicit decision. If no existing record owns the decision, the root may create an appropriate Concept or typed Relation. Do not add a parallel decision ledger. A delegated worker routes the exact decision delta to its assigned meaning owner.

For discussion-only work, link the governing user messages and source-anchored checks. Reuse checks while their governing decisions remain current. Identify affected Relations and Lens obligations, then return the decision or unresolved handoff to the native task context. Do not start implementation or testing solely because this skill ran.

If host mode or write permissions block a required update, including Plan mode, hand off the exact unsaved decision delta and its intended record destination. Do not claim it was saved.

## Reconcile changed implementation or evidence

Use the comparison and repair steps in this section only when implementation or evidence changed, or an actual mismatch needs investigation.

Select the affected Concepts and Lenses. Read governing prose, conditions, exceptions, selectors, and check definitions. Compare actual effects with the intended behavior and pre-change account. Follow [Applying Conceptor](../../references/applying-conceptor.md#compare-results-and-reassess-the-premise) to identify missing consumers or a faulty premise. Maintain affected Lens membership and evidence declarations through their assigned owner.

Use `reconcile` when reusing or checking these bindings answers a current question. Set `runChecks: true` only when native checks are needed. Batch related checks at a useful integration point; a new edit or commit alone does not invalidate every result. See [the reference guide](../../references/guide.md) for helper requests and receipt limits.

For each verdict, retain the condition, participants, selection status, evidence, status, and reason. Keep failed or unavailable observations alongside supported evidence. Empty required selection is unresolved unless the condition explicitly allows absence. A Lens with no checks supplies navigation, not behavioral support. Account separately for relevant prose obligations and native evidence outside helper receipts.

If there is a mismatch, retain the returned original mismatch in the native task context before changing code, selectors, checkers, or meaning. Determine whether the defect is in the realization, selection/binding, observation/check, or accepted meaning. Repair the responsible layer. Do not narrow a selector to hide a failure or change a condition merely to obtain a pass. Refresh affected Unit bindings and evidence applicability; preserve independently valid work.

## Retain lessons and finish

When a discovery changes where future work should look, update the existing Lens, Relation, or Concept that owns it. Preserve observed versus accepted status. When a reusable approach can guide future work, record a Pattern Candidate with examples, counterexamples, alternatives, and reopening assumptions. Do not promote it automatically. An explicit meaning decision can accept it and create or revise a scoped Lens. Preserve applicability and counterexamples. Repairs produced by that Lens are not independent evidence for it.

When repeated symptoms expose a faulty premise, use [Reassess from purpose](../../references/applying-conceptor.md#reassess-from-purpose) to compare the intended outcome with the responsible design. Preserve original evidence and resolve meaning changes with its owner. The native host owns repair, recovery and completion; Conceptor adds no task archive, commit policy or automatic gate.
