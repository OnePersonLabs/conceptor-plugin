# Recover meaning

Resolve the selected repository root. Conceptor is active when that root contains `.conceptor/`. A nested repository or worktree has its own root. If the selected root has no `.conceptor/`, continue through the native host without Conceptor.

Read the directive and identify the uncertainty that affects action. Read applicable repository instructions. Recover governing Concepts and their relevant full sections, reasons, exceptions, and reopening assumptions before choosing implementation paths. Requirements in the body remain authoritative even when no frontmatter condition names them.

Use typed Relations, Projection Units, Lenses, and Pattern Candidates to locate relevant constraints and consumers. Distinguish accepted meaning from observed relationships and candidate approaches. When upstream constraints or dependents matter, inspect incoming as well as outgoing Relations. Follow the bounded procedure in [Applying Conceptor](../../references/applying-conceptor.md#recover-the-governing-meaning); `focus.related` is not the full neighborhood.

Use a selective `focus` request when the optional helper reduces discovery work. Use `revisit` when previous evidence or bindings may be stale. Select Concepts, Lenses, paths, or a query; do not request an implicit global index. Read [the reference guide](../../references/guide.md) before constructing requests.

Compare the current question with relevant source scope and any explicitly supplied prior observations. A changed owner or contract can affect an unchanged consumer outside a Lens. Report the concrete discovery gap and which next action it affects. A provider result identifies its language, operation, scope, and gaps; it does not prove all consumers were found. Revalidate prior observations against current project and meaning bindings before reuse. Return source-anchored evidence and failures in the current conversation by default. Do not save copies merely because an observation failed. Persist evidence only for a named downstream consumer or live recovery need; record its source/version and validity, remove it when that need ends, and honor any maximum recovery window. Preserve authored meaning and source history in their existing owners.

For interrupted work, recover the caller's current request and inspect actual meaning files, source changes, staged changes, relevant commits, and applicable evidence. The caller owns durable task status and recovery; Conceptor stores no plan or request identity. Do not infer that an edit ran or claim exact replay protection from prior prompts. When purpose or premises changed, use [Reassess from purpose](../../references/applying-conceptor.md#reassess-from-purpose) as reasoning guidance. No saved comparison or session counter is required.

Give the root a compact packet: governing meaning, changed rule, actual participants and relevant transitions, currently applicable evidence and its validity, binding gaps, ownership, and the next useful action. Link detail instead of copying inventories. The root decides shared meaning, Lens updates, and delegation. Stop discovery when remaining uncertainty cannot change the next commitment. Withhold a dependent action whose premise remains unresolved; continue independent safe work. If recovery requires a saved artifact, name its consumer, owner, source/version binding, disposal condition, and maximum recovery window; arrange cleanup when the consumer completes, the work is cancelled or superseded, or that window expires. Do not create a durable packet or evidence archive by default.
