# Comparison before coding: correction and repeat trial

The repeat trial saved a substantive comparison, obtained independent architecture review, and completed its assessment before its first implementation edit. It then connected changed sensor evidence to shared-model learning and actual completed, recorded device output. The comparison-before-coding correction is verified for this supervised run. Final resource acceptance failed, so the Steady Helm candidate remains isolated and unaccepted for integration. A comparative efficiency improvement remains unestablished.

## Why the first hook was insufficient

The first trial received the reminder and read the procedure. Routing worked. The hook supplied context but did not control the transition into implementation. The runtime accepted completion without reading or binding a comparison account, and the lifecycle wording could be read as keeping assessment open through implementation review. The agent began editing at 07:13:20 UTC, recorded a candidate at 07:25:10, and completed assessment at 07:55:32. That ordering made the account retrospective.

The original instruction already required a visible comparison before implementation, so ambiguous completion wording explains only part of the failure. The implementation-focused assignment and permission to stop at an internal prerequisite also plausibly contributed. The trace cannot establish the agent's private reasoning.

## Projector correction

Local source commit `0c60de04` makes assessment completion require a saved account covering governing outcomes, the clean candidate, comparison, decision, connected boundary, validation and review. The runtime binds the account's bytes to the current candidate. Missing, changed or unbound accounts make reassessment due.

A native pre-tool hook holds ordinary shell, patch and initial delegation calls while assessment is due or active. Explicit assessment work remains available for discovery, bounded probes and planning. Required architecture review precedes completion; implementation and its code review follow it. The existing cost-adjusted compaction cadence remains in place.

This is a cooperative workflow guard. Field presence and byte identity do not establish sound reasoning. Assessment declarations cannot prove arbitrary scripts read-only, and existing interactive sessions and worker follow-up messages fall outside the fresh-call hook. Native review and observed work remain necessary.

Independent source review accepted the change. The full source suite passed 61 checks. The supported local refresh installed the Windows copy, verified all three hook trust entries, and passed the OPL configuration and global-instruction checks. Installed runtime and gate bytes match the reviewed source. No source push or product publication occurred. The same unrelated WSL marketplace registration still prevents WSL refresh and remains tracked on issue 2.

## Supervision and scope

The child initially treated a phone command-queue failure as blocking all consumer expansion. Focused independent review traced the actual producers: the selected simulator directly constructs Runtime and supplies reports and completed display events without that phone queue. The parent interrupted at a settled tool boundary and continued the same session with that dependency corrected. Shared lifetime and resource obligations still apply to the selected simulator experiment. Phone and general release admission remain separate obligations.

This intervention is counterevidence to autonomous self-correction. Stronger instructions, knowledge of the first failure, explicit parent review and supervision also differ between trials. The run cannot isolate the hook's contribution or establish a causal time saving.
